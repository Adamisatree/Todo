# Linea Tasks · 常见问题与故障排查

> 适用范围：本仓库 GitHub Actions 构建的 Windows x64 安装程序、macOS Intel / Apple Silicon 的 DMG 和 ZIP。**遇到 macOS“文件已损坏”请先看第 1 节。** 处理前不要删除已有任务数据。

## 先确认你下载了什么

1. 到 [Desktop builds 构建记录](https://github.com/Adamisatree/Todo/actions/workflows/build.yml)选择**最新且显示绿色成功**的一次运行，在页面底部下载 `Linea-macOS` 或 `Linea-Windows`。不要从不明站点下载，也不要使用失败运行的残留文件。
2. GitHub Actions 下载的是一层**构建产物 ZIP**。解压它之后，macOS 会看到两个芯片架构各自的 DMG/ZIP，以及 `SHA256SUMS.txt`；Windows 会看到 EXE 和校验文件。
3. macOS 点左上角苹果菜单 → **关于本机**查看芯片。M1/M2/M3/M4 等选择文件名含 `mac-arm64` 的版本；Intel 选择 `mac-x64`。也可在“终端”输入 `uname -m`：`arm64` 对应 Apple Silicon，`x86_64` 对应 Intel。
4. macOS 使用 DMG：打开 DMG，把 `Linea Tasks.app` 拖到“应用程序”，**退出 / 弹出 DMG 后**从“应用程序”打开。使用 ZIP：用系统“归档实用工具”解压内层 ZIP，把 `.app` 拖到“应用程序”；不要直接从压缩包或 DMG 内运行。升级时先完全退出旧应用再替换。

### 如何校验下载文件

从同一次构建的产物中取 `SHA256SUMS.txt`，它列出内层 DMG/ZIP（或 EXE）的 SHA-256。校验前确保文件和校验文件在同一文件夹。macOS 在该文件夹中运行：

```bash
shasum -a 256 "Linea-Tasks-1.1.0-mac-arm64.dmg"
cat SHA256SUMS.txt
```

文件名中的版本和架构以实际下载为准；**比较两行最左侧的 64 位十六进制摘要是否完全相同**。Windows 可在 PowerShell 运行 `Get-FileHash '.\Linea-Tasks-1.1.0-win-x64-setup.exe' -Algorithm SHA256`，再与同包内的 `SHA256SUMS.txt` 对照。旧构建可能还没有校验文件：建议改用提供校验文件的最新成功构建。如果摘要不同，请删除下载文件并重新下载，**不要尝试绕过系统安全检查**。

> 校验值只说明文件与该次 CI 生成的文件一致，并不能代替开发者签名、公证或对来源的判断。

## 1. macOS 弹出“‘Linea Tasks.app’已损坏，无法打开。你应该将它移到废纸篓。”

这句话**不总是表示文件内容真的坏了**。未经 Apple Developer ID 签名与公证的应用，在带有互联网下载隔离标记（quarantine）时，某些 macOS 版本会这样提示。当前项目采用临时的 **ad-hoc 代码签名**，不是 Apple 开发者签名，也没有公证；因此即使 CI 打包成功，系统仍可能拦截。请按顺序处理：

1. **先不要点“移到废纸篓”**。按照上面的步骤确认下载来源、芯片架构、完整解压、安装位置和 SHA-256。若实际出现“包含恶意软件”或杀毒软件明确报告威胁，请停止，不要执行下面的隔离标记操作。
2. 可以先在 Finder 的“应用程序”里右键（或按住 Control 点击）`Linea Tasks.app` → **打开**，按提示确认；也可以到 **系统设置 → 隐私与安全性** 查看是否出现“仍要打开”。注意：对于“已损坏”提示，此方式**未必可用**。
3. 如果确认来自本仓库的可信构建、哈希一致，而且仍提示“已损坏”，先在终端查看该应用的下载隔离标记：

   ```bash
   xattr -l "/Applications/Linea Tasks.app"
   ```

   如果能看到 `com.apple.quarantine`，可以**仅针对这一个已核实的应用**移除该标记，然后重新打开：

   ```bash
   xattr -dr com.apple.quarantine "/Applications/Linea Tasks.app"
   open "/Applications/Linea Tasks.app"
   ```

   如果安装在自己的 `~/Applications`，请把上述路径改为 `"$HOME/Applications/Linea Tasks.app"`。不要对整个“应用程序”文件夹执行命令；不要关闭 Gatekeeper、SIP，也不要用 `sudo spctl --master-disable` 之类的全局绕过命令。移除隔离标记会降低 macOS 对**这一个副本**的首次运行保护，请只在信任来源并完成校验后操作。
4. 如果提示“Operation not permitted”：在 Finder 中把应用放进自己可写的 `~/Applications`，退出 DMG，检查终端是否对该位置有访问权限，再使用正确的实际路径重试。不要为了省事直接关闭系统保护。
5. **如果移除隔离标记后仍无法打开**，不要反复移除标记。检查签名：

   ```bash
   codesign --verify --deep --strict --verbose=2 "/Applications/Linea Tasks.app"
   ```

   如果出现 `code object is not signed at all`、`invalid signature`、`a sealed resource is missing or invalid` 等错误，请删除**应用程序副本**（不是任务数据），重新从最新成功构建下载并解压；若仍失败，按文末模板反馈。正常的最新构建在 CI 中会对 Intel 和 Apple Silicon 的 `.app` 执行同样的签名校验。`spctl -a -vv` 因**未公证**而显示 `rejected` 并不一定表示文件被篡改；请不要把它当成唯一判断依据。

**长期解决办法**是使用有效的 Apple Developer ID 证书签名并完成 Apple 公证；这需要开发者账号和相应凭据。当前构建没有这些条件，ad-hoc 签名与移除隔离标记都不能代替公证。

### “无法打开，因为无法验证开发者”与“已损坏”是同一回事吗？

不是。前者通常是 Gatekeeper 对**未公证开发者**的拦截，可以先试 Finder 右键 → 打开，或“隐私与安全性”中的允许按钮。后者也可能由下载不完整、解压损坏、架构不匹配或签名无效造成，所以应该先核对来源、架构和 SHA-256，再按照第 1 节诊断。**如果系统明确说应用包含恶意软件，不要强行打开。**

## 2. macOS 双击后没有反应 / 立即退出

- 确认已从 DMG 或 ZIP **完整复制**到“应用程序”并弹出 DMG，使用与芯片匹配的版本；系统版本过旧也可能无法运行较新的 Electron，请尝试更新 macOS。
- 在终端运行 `open "/Applications/Linea Tasks.app"`，观察是否出现提示；签名检查用上面的 `codesign --verify`。若签名失败，重新下载，不建议强制重签来掩盖错误。
- 如果能打开但界面空白，请记下 macOS 版本、芯片型号、安装包完整文件名及复现步骤，在仓库提交 Issue。不要把任务数据文件或包含隐私的截图直接公开。

## 3. Windows 显示“Windows 已保护你的电脑”

这是 SmartScreen 对尚无信誉/未使用代码签名证书的 EXE 的常见提示，**不自动代表安全**。先确认来自本仓库的成功构建，并按上文比较 EXE 的 SHA-256。确定可信后可选择“更多信息 → 仍要运行”；若杀毒软件报告具体威胁，请停止并反馈，不要关闭杀毒软件或添加全局白名单。

## 4. 安装、升级、卸载与任务数据

- **数据在哪里？** 桌面应用使用 Electron 的用户数据目录（通常 macOS 为 `~/Library/Application Support/Linea Tasks/`、Windows 为 `%APPDATA%\Linea Tasks\`）。任务文件是 `linea-data.json`，上一次写入的备份是 `linea-data.json.bak`。请先在应用内 **设置 → 数据管理 → 导出** 备份 JSON。
- **重新安装会丢数据吗？** 正常替换应用程序不会主动清除用户数据。不要手工删除用户数据目录；卸载应用之后，若要彻底清除，先确认备份已可用，再自行删除对应用户数据目录。
- **如何换设备？** 在旧设备导出 JSON，在新设备导入。导入会**替换新设备现有全部任务和项目**；先导出新设备数据以便回退。没有账户或自动云同步。
- **数据读取失败怎么办？** 不要反复覆盖原文件。先退出应用，复制 `linea-data.json` 和 `.bak` 到安全位置，再尝试从之前导出的 JSON 导入或请维护者协助。程序会在主文件损坏时尝试读取 `.bak`，但 `.bak` 并不能代替定期手动导出。
- **浏览器预览里的任务不见了？** 预览把数据保存在该浏览器的 localStorage；与桌面版的数据目录相互独立。清除浏览器站点数据、换浏览器或换设备都不会自动同步。请用 JSON 导出/导入迁移。

## 5. 功能相关疑问

| 现象 | 检查与处理 |
|---|---|
| 没收到任务提醒 | 设置任务的**日期 + 具体时间 + 提醒提前量**，在“设置”启用提醒，允许系统通知权限；应用需要保持运行，关闭后不会在后台继续提醒。 |
| 完成重复任务后没出现下一次 | 任务需要同时设置**重复规则和截止日期**。每天/工作日可在任务详情设“每天完成次数”：当天未达目标会留在今天，达标后才排到下一个日期。 |
| 想跳过今天的单词 / 今天多做几遍 | 任务行或详情点“跳过”会按本机日期排到下一次，跳过不算完成；设置每天目标次数可以同一天完成多遍，额外练习点“今天加练”且不会推迟原计划。 |
| 日期不对 / 任务跳到很远的未来 | 首页显示“本机时间”，不会查询网络时钟。先检查系统日期、时区、自动设置时间是否正确；若之前的版本曾把重复任务排到远期，建议导出备份后在任务详情手动把截止日期改为今天，并按需设置每天次数。新版本完成或跳过会以本机日期安排下一次。 |
| 首页总时长与预想不一致 | “今日任务总时长”只统计今天及逾期未完成任务的预估；每天多次任务按**剩余次数 × 每次预估时长**计算。未设置时长的任务不算进分钟数，卡片会显示未估时数量。切到“所有任务”可看全部待办的估时。 |
| 手动排序怎么保存 | 在任务列表右上角选“手动排序”，拖动左侧把手，或用上下箭头调整。手动排序针对当前可见列表，保存后切换视图也会沿用其顺序；换成其他排序方式只是改变显示顺序，不删除手动顺序。 |
| 搜不到任务 | 搜索会查标题、备注、标签、子任务和项目；归档任务不包含在普通全局搜索里，请切到“归档”查看。也检查优先级筛选是否启用。 |
| 专注计时器不准确 | 计时器在应用运行期间使用墙上时间推进；退出应用不会继续计时，也不会跨次启动恢复。 |
| 批量删除后找不到任务 | 点击操作提示中的“撤销”可立即回退一次操作；提示消失后不可通过垃圾箱恢复，请从先前导出的备份还原。 |
| 导入失败 | 确认是本应用导出的 `.json`、格式未被手工修改，且文件可读取。导入会替换当前数据，先另存当前备份。 |

## 6. 报告问题时请提供什么

请在仓库提交 Issue，提供以下信息，方便区分安装、签名与数据问题：

```text
系统：macOS / Windows 版本：
芯片：Apple Silicon / Intel / Windows x64
来源：哪一次绿色成功的 Actions 运行链接
下载文件的完整名称：
精确报错文字或已打码截图：
是否核对过 SHA-256：是 / 否
是否安装到“应用程序”并弹出 DMG：是 / 否
macOS codesign --verify 的输出（如适用）：
可复现的操作步骤：
```

请**不要**在公开 Issue 中上传自己的 `linea-data.json`、导出备份、个人任务内容、账号凭据或包含私人信息的系统日志。
